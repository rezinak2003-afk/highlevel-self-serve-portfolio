KB-001 · Add a new lead without losing context Getting started

Use this when: a new person asks for information, starts a trial, or requests a callback.

Before you begin: check whether the person already exists. Use fictional data only in practice accounts.

  1. Open the CRM's Contacts area and choose the option to create a contact.
  2. Enter the minimum useful details: name, work email, company, source, and the reason they contacted you.
  3. Search for the email address before saving if you suspect a duplicate.
  4. Record the customer's goal in a note or approved field using neutral, factual language.
  5. Create or associate a deal only when there is a genuine sales opportunity; do not invent deal values.
  6. Set a next action and due date so the record tells the next teammate what should happen.

Expected result: one accurate contact record with context and a clear next step.

Quality check: can a teammate understand why the person reached out without asking you to repeat the conversation?

Reference: HubSpot CRM overview.

KB-002 · Move a deal forward and set the next action Lead management

Use this when: a lead has replied, completed a discovery step, or begun a trial.

  1. Open the deal record and check the most recent interaction.
  2. Choose the stage that reflects what has actually happened—not what you hope will happen.
  3. Add a short note with the last contact date, the user's stated goal, and any open question.
  4. Create one specific next action: “Send setup checklist by Thursday” is clearer than “follow up”.
  5. Assign an owner and due date according to your team's process.
  6. After completing the action, log the result and update the next step or stage.

Expected result: the pipeline reflects reality and every active deal has a meaningful next action.

Stage discipline: define entry criteria for each stage. For example, mark “Trial started” only after a trial actually begins; mark “Converted” only when the agreed conversion event has occurred.

Reference: HubSpot Academy — designing a sales process.

KB-003 · Draft a welcome email that sets clear expectations Messaging

Use this when: a new lead or trial user should receive a clear next step after an inquiry or signup.

  1. Confirm the trigger. Decide whether the message follows an inquiry, trial signup, meeting booking, or another explicit event.
  2. Set a single purpose. Tell the user what happens next; avoid stuffing the welcome email with every feature.
  3. Personalize accurately. Use a first name and relevant product context only when those fields are available and correct.
  4. Make help easy to find. Include one clear reply path or support link, plus an accurate expectation for response time.
  5. Test before enabling. Preview desktop and mobile layouts, test missing-name cases, verify links, and confirm the correct audience and consent settings.
  6. Check permissions and plan limits. Automation features vary by platform, tool, and subscription. If automated sends are not available, save the copy as a template and follow the approved manual process.
  7. Measure the result. Track delivery, replies, activation, or the next meaningful action—whichever fits the message's purpose.

Example subject: Welcome, [First name] — here's your next step

Example message: “Hi [First name], thanks for reaching out about [goal]. Your next step is [action]. You can reply to this email with questions, and our team will help you get started.”

Important: this portfolio demo does not send email. HubSpot's official documentation notes that full workflow automation is subscription-dependent; verify the current capabilities in your account before promising automatic delivery.

References: HubSpot automation availability · Workflow automation overview.

KB-004 · Troubleshoot a missing or duplicate contact Troubleshooting

Symptom: you cannot find a contact or suspect that two records represent the same person.

  1. Search by the exact email address, then try name and company. Remove accidental leading/trailing spaces from the query.
  2. Check saved filters, views, ownership filters, and archive/deletion areas if your CRM provides them.
  3. Compare the fields that identify the person before merging anything; a shared name alone is not sufficient proof.
  4. If records are duplicates, follow your team's merge procedure and preserve useful notes/activity history.
  5. If the record still cannot be found, confirm whether the form/import actually completed and check for an error or permission restriction.
  6. Escalate with the exact time, record identifier (if available), steps attempted, and screenshot with personal information redacted.

Expected result: one source of truth or a clear, actionable escalation—not a speculative second record.

KB-005 · Respond when a user is stuck during setup Troubleshooting

Use this when: a customer says they are stuck, sees an error, or cannot complete an onboarding step.

  1. Acknowledge the specific obstacle without blaming the user: “I can help you work through the setup step.”
  2. Ask one targeted question: “What do you see immediately after you select Save?”
  3. Confirm the expected outcome and the last completed step.
  4. Suggest one safe diagnostic action at a time. Do not ask for passwords, authentication codes, or payment details.
  5. If the issue persists, record the product area, browser/device, time, error text, and steps to reproduce; redact personal or confidential data.
  6. Explain the next step and give a realistic update expectation according to the team's support policy.

Example response: “Thanks for explaining where you're stuck. Let's check the step just before the error. After you select Save, what message appears? Please don't share your password or verification code. If it still fails, I'll record the error details and pass them to the right team.”

KB-006 · Write a support article users can follow Getting started

A useful help article lets a reader recognize their issue, complete the task, and verify the result with minimal back-and-forth.

  1. Title the task. Use a user-oriented phrase, such as “Add a new contact,” not an internal project name.
  2. State the scenario. Explain when the user should use the article.
  3. List prerequisites. Include required permissions, data, account access, and relevant plan limits.
  4. Write numbered steps. One action per step. Use the exact UI label only after verifying it in the current product.
  5. Describe success. Tell the reader what they should see after completing the task.
  6. Add troubleshooting and escalation. Cover the common failure path and what details to collect.
  7. Own freshness. Add an owner, last-verified date, and source links; review after product changes.

Article template: Purpose → Applies to → Before you begin → Steps → Expected result → Troubleshooting → Escalation → Sources / Last verified.

SUPPORT QUALITY

Every good answer should do four things

Be clear

Use plain language, short steps, and terms users recognize. Avoid internal jargon and unverified screen labels.

Be actionable

Give the user a next step and the expected result so they can self-check success.

Be safe

Never request passwords or verification codes; redact customer data in screenshots and escalations.

Be honest

Call out plan limits, unknowns, and when an issue needs escalation. Never imply an action occurred if it did not.
